# 报告助手与 Java 现有接口对接

- 维护日期：2026-10-30。
- 调用方：`agent-learning/` Python 终端助手。
- 测试网关：`https://testopen.beironsign.com`。
- 现状：复用 Java 已有接口，Python 未新增服务端登录路由或业务账号系统。

## 调用顺序和职责

```text
读取配置
  ├─ REPORT_USER_TOKEN 非空：复用该凭证
  └─ 未配置 token：
       ├─ test：测试接口获取验证码
       └─ sms：使用已获取的验证码
             ↓
       Java H5 登录返回 data.token
             ↓
查询当前用户的报告列表 → 用户选择 → 重新查询该页复核 → 请求报告正文
```

Java 校验验证码、确定业务用户、签发 token 并执行报告访问授权。Python 检查响应格式、
组织分页选择和绑定报告快照。客户端列表复核不能替代 Java 正文接口的逐请求授权。

以下响应仅列出 Python 当前消费的字段，示例数据全部虚构，不是 Java 的完整接口定义。

## 公共请求及响应约定

| 项目 | 当前实现 |
|---|---|
| HTTP 方法 | 下列四个接口均为 `POST` |
| 公共请求头 | `type: 3`、`isShareQuery: 0`，沿用 H5 普通查询约定 |
| 登录请求 | 不附带业务 token，也不使用模型 API Key |
| 报告请求 | 额外使用 `token: <Java 登录凭证>`，不是 `Authorization: Bearer` |
| HTTP 检查 | `raise_for_status()` 检查 HTTP 错误和重定向响应 |
| 业务成功 | 响应 `code` 为整数 200；没有 `code` 时读取 `status` |
| 解包结果 | 共用封装返回 `data`，各业务方法再校验其中字段 |
| 网络行为 | 超时配置 30 秒，关闭自动重定向和环境代理继承，业务封装不自动重试 |
| 异常显示 | 本地固定提示；不显示服务端 `msg/message`、响应正文或原始 HTTP 异常 |

报告客户端的固定错误名称分别为“报告列表接口”和“报告正文接口”，用于区分读取阶段。
读取失败后刷新报告列表，并在新列表之后、下一次输入之前显示固定原因；模板或本地字段资料
校验失败也在下一次选择前显示提示。以上仅调整 Python 终端交互，不新增接口或修改请求参数。

## 1. 测试通用验证码

`POST /report/openService/verify-code/sendGeneral`

仅 `REPORT_LOGIN_MODE=test` 使用，客户端要求网关地址与固定测试网关完全一致。
Java 方法接收 `@RequestParam`，参数放在 URL 查询串，POST 正文为空。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mobile` | string | 是 | 待登录手机号，与下一步登录必须一致 |
| `testUserName` | string | 是 | 测试接口要求的联调标记，来自 `REPORT_TEST_USER_NAME` |

最小响应示例：

```json
{"code": 200, "data": "123456"}
```

Python 要求 `data` 为 4 到 8 位数字字符串，收到空值或其他结构时停止，不继续请求登录。
参考 Java 实现把通用验证码写入 Redis，供后续登录校验；该测试链路不调用正式短信发送接口。

## 2. H5 登录

`POST /useragent/bg/companyUser/login`

参数放在 JSON 正文：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mobile` | string | 是 | 登录手机号；Python 先检查为有效格式的 11 位号码 |
| `smsCode` | string | 是 | 测试接口返回或用户已获取的验证码 |
| `type` | integer | 是 | 固定 3，H5 终端类型 |
| `registerType` | integer | 是 | 固定 3，H5 查询报告渠道 |

```json
{"mobile": "13800000000", "smsCode": "123456", "type": 3, "registerType": 3}
```

最小响应示例：

```json
{"code": 200, "data": {"token": "SYNTHETIC_BUSINESS_TOKEN"}}
```

Python 检查 `data.token` 是非空、有限长度的可见 ASCII 字符串后，交给报告客户端。
此检查只保证凭证可用作请求头，不判断 token 是否有效；有效期和权限由 Java 验证。
自动得到的 token 只保存在当前进程内存，不打印、不写回 `.env`，重启时重新登录。

## 3. 我的报告列表

`POST /report-server/my-report/query-user/page`

需要业务 token，请求 JSON：

```json
{"page": 1, "size": 20}
```

页码从 1 开始，每页固定 20 条。不传 `userId`，由 Java 根据 token 识别当前用户。

最小响应示例：

```json
{
  "code": 200,
  "data": {
    "records": [{"reportId": "SYNTHETIC_REPORT_ID"}],
    "total": 1
  }
}
```

`records` 必须是列表，每行含非空字符串 `reportId`；`total` 必须为非负整数。
`title`、`reportCode`、`completedAtText` 可用于终端展示，`orderId` 可补充本地绑定信息。
`total=0` 时显示暂无可用报告并正常退出。用户只能选择当前页序号，不能输入任意报告 ID。

## 4. 报告正文

`POST /core/mobile/report/getReportData`

请求前，Python 先重新读取所选页，确认该 `reportId` 仍在当前用户列表中；然后提交 JSON：

```json
{"reportId": "SYNTHETIC_REPORT_ID"}
```

Python 依赖的最小正文结构示例：

```json
{
  "code": 200,
  "data": {
    "report_id": "SYNTHETIC_REPORT_ID",
    "report": {},
    "template": {
      "theme": 3,
      "modules": [{"moduleId": 5, "moduleName": "虚构示例模块"}]
    }
  }
}
```

`report_id` 必须等于请求的 `reportId`，`report` 必须为对象。本地工具进一步校验模板主题和模块：
`template.theme` 必须是整数，精确匹配本地登记的 1、2、3、4、5、6、27、28、40、50、51、52。
字段查询只覆盖该主题及实际启用模块中已登记的路径，不执行表达式或 SQL。
未登记主题明确提示重选，不回退到 `theme=3`；模板或字段资料损坏另行提示。
正文按选择时的快照保存在内存；后续问答不逐轮刷新正文，重新选择报告会重建会话。

### Python 本地字段目录

`data/report_fields.json` 是通用字段资料，不是新增 Java 接口。格式为 `schema_version=2`，
`themes` 用主题编号的字符串作为键，各项包含整数 `theme`、本地名称 `theme_name`、
外观来源记录 `effective_theme` 和 `fields`。实际匹配只使用 `theme`，不按 `effective_theme` 回退。
原单主题结构仍可显式传入 `LocalReportTools(order, catalog)`，且必须与当前主题一致。

每条字段保留 `module_id`、`module_name`、`name`、`path`、`window`、展示规则、枚举及通用口径。
启用白名单取自当前报告的 `template.modules[].moduleId`。支持 `report` 下的对象路径、
`[数字]` 数组下标或对象数字键、`[]` 数组元素、`.*` 动态对象键。
`path` 中 `|` 分隔的候选依赖分别返回原值及提供状态，不执行逻辑运算或猜测回退顺序；
固定文案的 `path` 为空，只解释规则。缺失、null、空字符串和 0 继续区分。

多主题资料的导入来源、覆盖数量与限制见 [多版本开发记录](../../development/agent-learning/2026-10-30-multiple-report-themes.md)。

### Python 本地问法识别

`report_questions.LocalQuestionResolver` 只在当前主题启用字段中匹配口语、模块关键词、
字段别名和滚动窗口。返回的本地 `LocalQuery` 包含候选 `fields`、同指标跨周期 `scope`、
展示操作 `operation` 和本地提示 `message`，不属于 Java 接口或模型工具参数。
`Conversation` 的本地模式和AI失败回退使用该结果取值；只有加密历史保存成功才提交新的字段选择上下文。

多个候选最多显示6项，用户可用 `/pick 序号` 或“选择第1项”选定后读取；单字段选定后的
含义、取值和周期追问只复用本地上下文，同模块同字段名之外不自动替换。
窗口同时识别登记标签、字段名称及大小写路径编码（如 `_D7_`、`_d15_`、`_month12_`）；
申请总次数排除机构数和夜间等分项，档位不转换成精确次数。自然月、日期区间及多个不同周期要求进一步明确。
无法匹配时显示当前报告的可查模块，不把无匹配解释成零值或无风险。
“分析下我的报告”“请帮我分析一下我的报告”等完整整体问法返回模块引导；本地模式及 AI 失败回退均不把这些问题误判为某个指标或周期不存在。

本地关键词匹配不授予任意报告数据外发资格。旧 `template` 协议仍由
`report_privacy.approved_request` 独立批准枚举；终端已改用下述 `analysis` 策略。
本地识别的原始实现记录见 [自然问法开发记录](../../development/agent-learning/2026-10-30-natural-questions.md)。

### Python AI分析协议（不是新增Java接口）

用户于2026-10-31进一步明确报告业务内容只排除姓名、证件、手机号、地址，其他均可用于分析。`REPORT_EXTERNAL_MODEL=on` 时，终端允许通过本地检查的自然问题及按需读取的脱敏报告内容发送至所选模型厂商；文字、婚姻学历、案件明细、布尔、数组、对象和字段说明均可提供。运行凭据不进入消息。厂商配置见[模型接入说明](model-providers.md)，本次范围及验证见[开发记录](../../development/agent-learning/2026-10-31-report-data-scope.md)。业务登录、选报告及正文权限保持由Java负责；模型没有切换业务用户或报告的工具。

新策略调用顺序：

具体指标请求按型号选择参数：`glm-5.3-flash`、`glm-5.3-flashx`、`glm-5.3-flashx-legal` 使用 `thinking.type=enabled`、`max_tokens=8192` 和单次 SDK 请求 `timeout=90.0`；其他型号沿用 `disabled`、1800和30秒。整份报告的模块小结和整体总结统一使用8192、90秒，是否思考仍按型号决定。SDK请求级超时不进入JSON正文。具体问答保留最终6段、7次请求、12次工具调用和48项事实限制；整份报告使用下述独立预算。`reasoning_content` 始终不进入下一轮消息及本地历史。

1. `QuestionGuard` 在本地拦截四类个人信息及凭据的已知原值、标签和常见号码格式。失败时零模型请求，原问题保留本地；不让模型执行脱敏。其他普通报告文字、业务编号、邮箱和网站不再因类别或长度一律禁发。
2. 常见完整客服短句先由本地入口处理；完整“分析下我的报告”等整体问法直接进入模块总结。其余路由使用固定system及输入JSON `{"question":"当前通过检查的问题","has_previous_report":false}`。布尔状态仅表示是否存在上一报告上下文，不包含旧问题、字段引用、报告目录、数值或完整历史；有上下文的“那银行呢”“涉及几家”等承接问法按report、focused、use_previous=true分类，新话题仍独立判断。报告路由要求 `{"route":"report","use_previous":false,"scope":"overview|focused"}`，兼容缺省scope并按focused处理。报告与客服复合问题可另加 `service_topics:["refund"]`：先完成报告回答，再附本地客服说明。范围外要求 `{"route":"general","use_previous":false}`。单客服兼容 `{"route":"service","use_previous":false,"topic":"封闭主题"}`，多客服使用 `topics:["appeal","refund"]` 代替topic；列表必须含1至3个非重复封闭主题，拒绝自由文本、额外键和同时给topic/topics。不会因开头问候或客服咨询遗漏报告事实。
3. focused分支让模型自主使用下表工具，读完事实后单独调用 `submit_report_analysis` 提交结论；工具阶段不同时开启JSON响应模式。只追加验证后重建的查询调用及投影结果，不转发模型中间自由文本或推理内容。
4. focused结论要求 `{"sections":[{"text":"分析段落","sources":["f1"]}]}`，1到6段，每段引用本轮已读事实；本地检查引用、数字、个人信息及常见审批断言，只展示客服正文，不追加事实清单或读取范围。单个主评分段落使用本地核实的展示分数与等级短答，不展示底层值、区间边界或计算过程。缺失来源下的“不能按0次理解”等固定否定比较允许通过；独立肯定零值陈述仍须有零来源。明确否定“无风险/无逾期”的提醒不当成风险保证；同段其他肯定保证仍拒绝。最多5轮开放工具，第6轮只提供JSON结论模式；工具数或事实数达到上限时提前结束查询。异常仍分类回退本地。

overview分支由 `report_assistant/conversation/overview.py` 执行，属于Python本地编排，不新增Java接口或模型工具：

1. `LocalReportTools.current_modules()` 按当前 `template.modules` 数组顺序返回去重模块。名称优先本地字段目录，未登记模块使用经过标签检查的模板名。每模块读取当前可投影的全部登记字段，经既有 `FactProjection.read` 的12项出口分段过滤；无可投影字段的模块保留本地位置，不伪造数据。
2. 每批无工具JSON请求附 `{"question":"问题","modules":[{"module_ref":"m1","name":"模块名","facts":[已投影事实]}],"scope":{"stage":"modules","module_count":9,"confirmed_module_count":8,"batch_module_count":1}}`，模型返回 `{"modules":[{"module_ref":"m1","text":"一段模块概括","sources":["f1"]}]}`。scope由程序按当前报告计算，示例计数为虚构；最终总结使用stage=summary。范围元信息计入原100000字符预算，不附其他批次正文。给出的每个模块恰好一段；拒绝缺漏、重复、额外模块、跨模块来源、未读取来源、无来源数字、字段编号、技术清单及超长/多段正文。每段不超过450字，默认一句，确有关键记录或缺失需要说明时再补第二句。
3. 最后单独请求整体总结，输入仅为已核验模块的 `module_ref/name/text/sources`、不可解读模块名称及当前问题，不附原始字段或旧聊天。返回 `{"text":"整体总结","sources":["f1"]}`，来源须被模块小结引用，数字须已出现在对应小结。任何阶段失败都不发布部分模块答案。
4. 本地按模板顺序添加模块标题，最后添加“整体总结”；不追加字段清单、技术范围或统一免责声明，不显示来源编号。缺少内容的模块明确说明暂不能判断。加密保存成功后才提交完整答案及上下文，仍不存储供应商推理内容。

整体流程最多96个模块、4096个字段、每模块256项；每批最多8个模块、256项，问题及批次JSON不超过100000字符。全部批次先预检，最多32批；再加1次整体总结和可选1次语义路由，上限34次请求。整体总结JSON也限制100000字符。超限使用固定预算提示，整轮回退而非静默截断；没有可投影字段时不请求模型，直接说明。此流程不扩大字段权限，仍不发送四类个人信息或运行凭据。

`AnalysisFailure` 仅携带程序固定的超时、连接、服务拒绝、回答不完整、预算或最终回答校验失败提示；其他请求/工具校验异常使用固定校验提示，未知异常使用固定不可用提示。SDK请求、响应和异常正文均不加入答案或重试请求。思考模型整体分析失败不能仅凭原统一提示判断为隐私拦截或缺少字段。
终端在进入单轮处理前立即刷新接收提示，处理期间每10秒显示等待时间，返回或抛异常时停止提示；提示不表示模型阶段或完成比例，不进入模型消息与加密问答历史。会话及SQLite操作保留在调用线程，最终答案仍在全部校验与加密保存成功后刷新显示。请求超时是单次网络请求预算，整份报告多批请求可能累积超过90秒；没有增加自动重试或整轮强制超时。该交互调整不改变Java接口。
整份报告校验失败时，`AnalysisFailure.reason`继续为`answer`，可附`OverviewValidationError`类型的`validation`：仅含固定`code`、`stage=prepare/modules/summary`、批次与本批段落序号。终端增加封闭中文详情以区分结构、覆盖、来源、长度、数字、无依据结论或技术引用等原因。未知校验异常映射为通用详情，不拼接原异常、模块名称、业务标识或模型正文。预算和服务错误仍走原分类，不自动重试或发布已生成的部分小结。
数字检查认可严格三位分组的千分位写法，如`1,000`与来源`1000`等价；百分比须在引用来源中存在相同百分比，如页面已有的还款成功率`0%`，不因出现百分号一律拒绝。裸数字或小数不能授权百分比及自动换算，不支持的数字、比例和审批概率仍拒绝。整体总结的本地校验保留原来源的缺失状态，仅用于识别“不能按0次理解”等明确否定比较；数值仍只能来自已核验小结，不从原字段补出新数字。“不能确定/无法确认没有逾期”等否定判断不会被当作无逾期保证，同段新增的肯定保证仍拒绝。
完整有效日期按年月日整体核对：虚构示例`2024-05-07`与`2024年5月7日`、`2024/5/7`、`2024.05.07`等价，仅在识别到完整日期后把短横线作为分隔符、忽略月日前导零；其他负号保持原义。来源日期的各个数字不能授权拼成其他日期。模块小结与整体总结使用相同规则，原回答不改写；无效日期不进行格式等价化。此为Python本地回答校验调整，不改变Java接口。
否定判断同样支持“不能直接说明没有逾期”“无法直接确认无逾期”等紧邻动词的明确否定，以及“不能判断没有逾期或无风险”等同一否定动词下的并列结论；连接词仅允许或、和、以及、及、顿号，不跨逗号、分句、转折词或新增主语，后续单独的肯定保证仍按原规则拒绝。
“不能仅凭……判断整体无风险”可在同一短分句内识别，依据文字限80字符且原样保留，仅屏蔽被否定的结论；依据中出现转折、额外否定或独立风险保证不豁免。此识别不修改用户看到的答复，不替代来源数字与其他正文检查。
