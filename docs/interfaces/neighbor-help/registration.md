# 注册、可选邀请码与住址展示

- 日期：2026-11-03。
- 调用方：前端 `/login?view=register` 单页注册、账号登录及个人资料页。
- 本文描述本轮源码契约；当前已部署 Worker 是否支持，通过公开能力接口判断，不把本地测试当作线上升级。

## 注册能力

`GET /auth/registration-options`，无需鉴权、无请求体，不访问数据库。成功为 HTTP 200、业务码 200：

```json
{"code":200,"message":"ok","data":{"inviteCodeSupported":true}}
```

前端只有收到严格布尔 `true` 才确认邀请码支持。旧服务的 HTTP 401 / 404 作为未支持处理，不清除当前会话、不触发全局登录跳转；网络或其他服务错误与未支持区分。不填写邀请码时仍可使用原注册接口；非空邀请码在未确认支持时就地提示，不能静默丢弃后显示成功。

## 账号注册

`POST /auth/register`，无需鉴权，参数在 JSON 请求体。

| 参数 | 必填 | 当前规则 |
|---|---|---|
| `username` | 是 | 去除首尾空白；4–20 位 ASCII 字母或数字，统一小写保存；大小写不敏感查重 |
| `password` | 是 | 8–100 位，按原输入保存哈希，不发送确认密码 |
| `inviteCode` | 否 | 缺省、`null`、空串或纯空白存 `NULL`；非空字符串 trim 后限 4–20 位 ASCII 字母或数字，统一大写保存 |
| `nickname` | 否 | 兼容旧客户端；最多 30 字，缺省昵称为“邻居” |
| `building` / `unit` | 否 | 兼容旧客户端的可选数字资料；新注册页不收集，个人页可后补 |

邀请码仅保存到 `users.registration_invite_code` 作为来源备注，不校验邀请人、不授予居住认证、积分或其他权限。没有短信发送、验证码登录或邀请码生成接口。

成功条件为 HTTP 200 且 `code === 200`，`data` 含 `{ token, user }`。前端设置真实会话后返回注册前的来源；无来源回首页。注册、密码登录和微信登录均不回传密码或内部注册来源字段。

异常沿用统一协议：格式错误为 HTTP 400 / `1003`；用户名重复为 HTTP 409 / `1001`；限流为 HTTP 429 / `429`。表单在字段旁显示可定位错误并保留输入；请求过程中锁定再次提交，离开页面后不再应用迟到成功结果。密码不写入地址栏或浏览器草稿存储。

## 房号边界

- 公开或他人视角的 `POST /api/posts/list`、`POST /api/posts/detail` 中，`author.unit` 及兼容字段 `unit` 为 `""`；楼栋可见。服务端已验签且确认是作者本人时，可保留本人房号用于既有资料 / 编辑。
- `POST /api/me/get` 的本人资料继续返回自己的楼栋和房号；`POST /api/me/posts` 本人视角保持兼容。
- `POST /api/messages/thread` 的 `peer.unit` 固定为空串，不因私信关系公开他人房号；其他会话及未读契约不变。
- 新帖自动默认地点只带楼栋。`post.location` 是用户明确填写的公开文本，不自动清洗已存在帖子或草稿；历史文本中若已有房号，仍需作者自行编辑。
