## 需求与原因

用户最终给出 YomoaAI / UI Notes 参考，要求保留原项目布局，将视觉改成奶白底、黑色排版、糖果色功能区域与大眼胶质角色。此前对话内方案仅为预览；本记录对应首次将这一确定方向落到项目源码。原有线性图标调整和体验修复保留在工作区，后续视觉选择以本需求为准。

同日继续细化：用户认为角色仍然偏小，希望糖果色和卡片质感更接近参考，同时明确不改原布局。本次将角色绘制尺寸与布局占位分离，增强功能卡底色、叠层和内高光；在修改前记录首页及发布弹层的元素位置，调整后以相同虚构数据和视口核对。细化已完成，下方单独记录本轮验收。

## 方案与改动

- 保留首页品牌、问候、统计、公告、横排分类、双列瀑布流，以及原底栏固定定位和发布流程；不新增独立插画区，不更换路由、请求或数据契约。
- 全局主题改为奶白 / 中性深色背景与高对比操作色；彩色集中在分类入口、分类选择和已有装饰区域，普通帖子以清爽实底为主。
- 使用本聊天内 imagegen 生成的原创胶质邻里角色，透明图集已转换为 WebP；分类语义继续由文字与分类值共同表达，关键操作和导航沿用清晰线标。
- 动效仅在交互反馈中使用，并遵循减少动态效果偏好；不加入持续漂浮或自动循环的角色动画。
- 同步浏览器顶底栏色、MUI 主题及相关文档，避免首屏与切换主题时残留暖橙色。
- 新增 `GummyCharacter.jsx` 与透明 WebP 图集，`MenuSticker` 保留原调用接口；首页 / 发现分类、发布分类、无图详情和登录品牌使用同一套角色。未知分类回退线性图标，角色本身不进入读屏与焦点顺序。
- `HomeTop.jsx`、登录页与个人页沿用原布局，将已有装饰色改为粉、奶黄和淡紫；首页分类仍为每项 76px 的横滑入口，发布仍为原两列分类弹层，普通帖子和实物封面不改为插画。
- 复查修正了新组件使用 `Object.hasOwn` 带来的旧版 Safari 运行时风险，改用兼容的自有属性检查；错误 Toast 改用 `--color-on-danger`，避免深色浅粉底配白字。减少动态效果变量移到默认 Token 区，防止后面的默认声明覆盖用户偏好。

## 整页主题底色与弹窗操作统一

用户要求登录、注册与进入后的页面在同一主题下共用基础背景，让 iOS 顶底安全区连续；同时要求登录按钮参照注册按钮，协议等弹窗的关闭按钮与上方拖拽提示条采用浅色黑、深色白。原问题来自登录独立渐变和 body 覆盖、业务页头部整片异色、主题在 effect 后更新，以及页面背景动画与浏览器栏即时着色时机不同。

### 颜色与形象 / 表情独立组合
