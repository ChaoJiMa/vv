# 问答失败的私有诊断记录

- 日期：2026-11-16。
- 范围：`agent-learning/` 的模型问答、整体分析校验、加密历史和维护入口。
- 状态：已完成本地实现与离线回归；待用户重启客服进程后新版本才会记录现场失败。

## 需求与原因

用户希望每次失败有可供维护人员排查的原因，但不向客户展示技术细节。此前 `Conversation` 只把 `AnalysisFailure` 的固定原因和整体校验位置临时拼入回答；所选模块回退甚至不显示这段提示。`HistoryStore` 只保存最终问答，模型异常映射后没有可聚合的独立诊断。SDK/HTTP 原始日志已被关闭，无法从已有数据可靠还原失败原因。

## 方案与改动

- 在现有 `%LOCALAPPDATA%/ReportAssistant/history.sqlite3` 增加独立 `diagnostics` 表，沿用当前 Windows 用户的 DPAPI 加密及 SQLite 事务。仅接受封闭的失败类别、固定问答范围和整体分析校验元数据；不接收原问题、回答、报告绑定值、模型草稿、SDK 异常、URL 或凭据。
- `Conversation` 在模型失败、请求或事实守卫失败、未启用模型及旧模板模型选择失败时先记诊断，再按原本的范围进行本地回退；模型语义路由与整体/具体问题的实际执行分支分别标记。所选模块回退的结构值占位、投影拒绝、无可解读字段和预览数量上限也有固定类别，本地回退异常另记 `local_processing`，同一轮可能产生多条事件。诊断写入失败则终止本轮，不继续提交答案及会话状态。客户只见统一的未完成提示或经本地核实的内容，校验类别、阶段、批次与位置只在维护记录中。
- `OverviewValidationError` 向诊断提供固定映射后的详细标签，不复制底层异常文本。模型服务异常只提取整数 HTTP 状态码，便于维护人员区分鉴权、限流和服务故障；正文和请求地址仍被丢弃。
- 新增维护脚本 `scripts/inspect_failure_diagnostics.py`，按原因、范围和固定校验子类汇总并显示最近记录；`--summary-only` 可隐藏逐条输出。脚本使用 SQLite 只读连接，旧库无诊断表时不创建或迁移。此入口不接入客户问答或 `/history`。README 与模型接入说明同步记录调用范围和权限边界；无 Java API 变化。

## 使用与限制

维护人员以启动客服的同一 Windows 用户运行 README 所列脚本读取诊断；DPAPI 不提供独立的业务管理员鉴权。记录从本次版本运行后开始产生，旧失败无法补录。整体分析的固定校验标签可定位数字、来源、范围等问题及批次；focused 回答校验暂只归类为 `answer`，无法仅凭日志确定每句自然语言错误。诊断不保存原文，因此复核具体回答仍需在授权范围内另行使用本地加密问答历史。未读取真实报告或回传用户数据。
