# 问答失败的私有诊断记录

- 日期：2026-11-16。
- 范围：`agent-learning/` 的模型问答、整体分析校验、加密历史和维护入口。
- 状态：已完成本地实现与离线回归；待用户重启客服进程后新版本才会记录现场失败。

## 需求与原因

用户希望每次失败有可供维护人员排查的原因，但不向客户展示技术细节。此前 `Conversation` 只把 `AnalysisFailure` 的固定原因和整体校验位置临时拼入回答；所选模块回退甚至不显示这段提示。`HistoryStore` 只保存最终问答，模型异常映射后没有可聚合的独立诊断。SDK/HTTP 原始日志已被关闭，无法从已有数据可靠还原失败原因。

## 方案与改动

- 在现有 `%LOCALAPPDATA%/ReportAssistant/history.sqlite3` 增加独立 `diagnostics` 表，沿用当前 Windows 用户的 DPAPI 加密及 SQLite 事务。仅接受封闭的失败类别、固定问答范围和整体分析校验元数据；不接收原问题、回答、报告绑定值、模型草稿、SDK 异常、URL 或凭据。
- `Conversation` 在模型失败、请求或事实守卫失败、未启用模型及旧模板模型选择失败时先记诊断，再按原本的范围进行本地回退；模型语义路由与整体/具体问题的实际执行分支分别标记。所选模块回退的结构值占位、投影拒绝、无可解读字段和预览数量上限也有固定类别，本地回退异常另记 `local_processing`，同一轮可能产生多条事件。诊断写入失败则终止本轮，不继续提交答案及会话状态。客户只见统一的未完成提示或经本地核实的内容，校验类别、阶段、批次与位置只在维护记录中。
- `OverviewValidationError` 向诊断提供固定映射后的详细标签，不复制底层异常文本。模型服务异常只提取整数 HTTP 状态码，便于维护人员区分鉴权、限流和服务故障；正文和请求地址仍被丢弃。
- 新增维护脚本 `scripts/inspect_failure_diagnostics.py`，按原因、范围和固定校验子类汇总并显示最近记录；`--summary-only` 可隐藏逐条输出。脚本使用 SQLite 只读连接，旧库无诊断表时不创建或迁移。此入口不接入客户问答或 `/history`。README 与模型接入说明同步记录调用范围和权限边界；无 Java API 变化。

## 使用与限制

维护人员以启动客服的同一 Windows 用户运行 README 所列脚本读取诊断；DPAPI 不提供独立的业务管理员鉴权。记录从本次版本运行后开始产生，旧失败无法补录。整体分析的固定校验标签可定位数字、来源、范围等问题及批次；focused 回答校验暂只归类为 `answer`，无法仅凭日志确定每句自然语言错误。诊断不保存原文，因此复核具体回答仍需在授权范围内另行使用本地加密问答历史。未读取真实报告或回传用户数据。

## 2026-11-18 详细校验证据

用户要求日志足以继续分析失败原因。原有固定子因只能定位代码分支，无法判断来源是统计周期还是持续时长，也无法区分首次失败和纠错后失败。

- 新增 `security/validation_diagnostics.py`：把被拒段落与实际引用的来源整理为有界角色对照。记录段落字符数、来源数、来源引用序号、类型/状态、规范化统计周期、时长的年/月单位与中文/数字写法、归一化月数与精确/上下限边界，以及同指标和同值同边界匹配情况。指标名称仅在内存用于对照，不落盘；不保存原问题、草稿、字段名称、报告原文或凭据。统计周期按校验入口剔除后单列，不能误记为个人持续时长。
- `ReportOverview`统计模块/总结请求数、本次流程耗时、是否使用数字纠错；只保留第一次纠错原因及最终失败的阶段/批次/位置/子因和角色证据。若首次纠错成功但后批仍失败，两处位置均可见；不会增加模型请求、放宽校验或改变原有一次纠错预算。
- `HistoryStore`仅对带详细证据的记录使用v3；无证据仍为v2，兼容v1/v2读取。写入和读取共用严格白名单，拒绝额外键、自由文本、无界列表和布尔伪整数。每次最多2次校验尝试，每次最多12条来源和12个回答时长、每来源最多12个时长，超量标记截断；复用原DPAPI独立诊断表。
- 维护脚本逐条展示执行证据和时长角色对照；`--summary-only`仍仅汇总固定类别，客户回复和`/history`不展示维护证据。角色比较属于观察，不自动判断模型错误或校验误报。

## 2026-11-19 模块取值与展示缺口

用户看到信用查询记录提示信息暂未提供。该轮整体分析成功，旧日志没有保留模块取值状态，因此无法追溯这一轮的字段是否缺失、为空或没有匹配的展示规则。用本地字段目录和虚构数据，分别复现了模块容器缺失与已有字段未支持展示。

- 完整及所选模块分析复用既有取值流程，分别统计正文读取和最终展示状态。登记路径都位于同一个数字模块根时，记录容器缺失、空白、空对象或列表、类型不符或存在。读取命中复杂容器时，计数不能证明容器中的每个叶子都有值。展示转换器缺失单独计数，即使正文字段缺失也能看见规则缺口。
- 成功生成模块小结后，有缺口的模块汇成一条 `module_availability` 事件，使用同一 DPAPI 加密库和独立诊断事务。诊断只保存固定状态、计数和本地目录模块号。未登记模块按其在解读范围内的位置定位。读写均校验结构及计数。旧诊断可由更新后的维护脚本读取。
- 诊断数据仅保存于本地维护记录。加密诊断写入失败时依原规则停止本轮。诊断记录先于问答写入，问答保存失败时仍可保留已经生成的诊断。只记录新执行的模块分析，无法从旧回答恢复取值状态，也无法从快照判断上游为何没有返回指定字段。原模块取值和展示规则未在本次调整。
