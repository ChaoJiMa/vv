# 整份报告按模块顺序总结

- 日期：2026-10-31。
- 范围：agent-learning 的整体报告意图、模块读取、总结输出和回归验证。
- 状态：实现、文档、离线验证及DeepSeek虚构报告实连已完成；后续Sol兼容网关虚构报告验证也通过，真实用户报告未验收。

## 需求与原因

用户要求“分析下我的报告”从当前报告的第一个模块开始逐模块概括，最后做整体总结，参考此前小贝对话；不逐字段解说或附上冗长事实清单。原流程按字段目录及调用预算选局部模块，渲染器又强制追加每项原始事实，无法保证模块顺序、覆盖和最终总结。

## 方案与改动

增加独立整份报告流程：以当前模板的模块数组顺序为准，读取各模块全部已登记且允许分析的字段，分批生成简短模块总结，最后另生成整体总结。引用留作本地校验，不展示字段编号或事实附录。没有可总结信息的模块明确保留占位，不跳过或推断。

核对12个主题的静态目录后发现每主题有657至1786条登记字段、最多87个模块，单模块最多146条；仅选少量代表字段仍可能遗漏模块后面的重要内容。因此最终实现不抽样，仍用既有投影出口每12项分段过滤，再按模块与请求长度组批。

继续复用当前报告绑定、已有四类个人信息过滤、业务凭据隔离和加密历史，不覆盖其他任务的数据范围变更。具体指标问答沿用原工具流程。新流程有独立模块/字段/请求上限，避免以旧字段工具预算截掉后半份报告。

- `report_tools.py`：增加本地 `current_modules()`，按模板数组顺序去重，保留无可读字段模块；不以字段目录顺序或模块编号排序代替报告顺序。
- `report_questions.py`、`report_analysis.py`：完整整体问法直接进入模块流程，其他自然说法由语义路由选择overview/focused；仍兼容旧报告路由结构。整体解读不复用上轮问题或字段事实。
- `report_overview.py`：最多96个模块、4096个字段、每模块256项；每批至多8个模块、256项和100000字符，最多32批，再加1次独立整体总结及可选1次路由。每次模块/整体总结请求使用8192 tokens与90秒超时；超限整轮回退，不静默截断。
- 所有模块小结必须覆盖当前批次，拒绝缺漏、重复、跨模块引用、无来源数字、技术引用和多段/超长正文。整体总结只接收核验后的小结，不再接收原始字段；数字须已出现在所引小结中。结果按本地模块顺序渲染，来源编号不显示。
- 提示词参照此前[小贝客服对话记录](2026-10-30-xiaobei-service-conversation.md)，模块通常两句话，归纳主要情况，减少规则和免责声明重复；不复制示例中的个人资料、分数或未经核实评价。
- `tests/test_overview.py` 增加22项回归。旧工具循环测试改用具体指标问法，保留工具参数、预算、隐私和SDK断言；新套件单独覆盖整份报告。`report_projection.py`仅同步类说明中的预算归属，不改变脱敏逻辑。
- README、Java接口说明中的Python协议、模型接入文档与文档索引同步更新。本次没有新增Java接口，没有更改本机厂商或密钥配置，也没有提交、推送或部署。

## 使用与限制

退出旧终端进程，重新运行 `agent-learning/main.py`，开启AI后输入“分析下我的报告”。系统按当前报告的首模块开始归纳，最后整体总结；具体指标仍可追问或用本地命令查询。

覆盖范围是当前模板中已登记且通过既有投影的字段，不等于所有原始报告内容均可外发；仅含被过滤个人字段的模块提示暂无可解读内容。正文很大、超过字段/模块/批次上限时整轮回退，模块较多时耗时与模型用量增加。缺失不作零值，零值不直接评价为无风险；数字与规则检查不能完整证明自由文本推理正确，实际文案仍受模型输出影响。

同日继续按用户反馈调整客服表达：整份报告不再附统一边界尾注，评分模块可使用本地核实后的页面分数与等级；具体指标也取消事实附录与读取过程。规则、边界验证及Sol虚构分数实连结果统一维护在[客服表达记录](2026-10-30-xiaobei-service-conversation.md)。
