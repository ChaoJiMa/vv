# 报告模型数据范围调整

- 日期：2026-10-31
- 范围：agent-learning 的 analysis 策略、报告出站过滤与接口说明。
- 状态：实现、说明及离线验证已完成；真实业务与模型服务未实连验证。

## 需求与原因

用户明确要求报告中仅姓名、证件、手机号、地址不给模型，其他内容均可用于分析。
原实现只开放带统计名称的数值标量，并把所有报告自由文本和业务编号登记为私有值，
使婚姻、学历、案件明细等无法参与模型分析，也会误拦截普通报告文字。

## 方案与改动

按当前主题与已启用模块提供已登记字段，允许文字、布尔、数组、对象和字段解释；
在本地递归移除四类个人字段，替换已知个人值及常见手机号、证件格式。
业务客户端凭据仍只用于登录和报告读取，不进入模型消息。保持报告绑定、引用校验、
工具预算及加密历史；兼容 template 策略继续使用原枚举协议。
同步 README、Python 工具接口说明、项目技能中的历史边界及文档索引。

- `report_redaction.py`：集中四类字段别名、号码格式、已知值收集和文本替换；
  区分机构名称与机构内部的个人姓名，支持姓名列表和JSON字符串。
- `report_tools.py`、`report_projection.py`：取消普通文字及业务编号的通用禁发，
  允许非统计字段及复合值；按目录标签识别缩写个人字段，收集时也检查未启用模块，
  防止同一姓名在备注里重复出现。过滤只创建副本，本地查询保留原值。
- `report_analysis.py`、`main.py`、`report_session.py`：更新工具描述、事实展示、启动提示和中文职责说明。
- 更新旧测试的授权范围断言；保留凭据、报告绑定、非法工具、数字来源及加密历史检查。
  工作区另有并行新增的整份报告模块总结流程，本轮保留该实现；原工具循环测试改为具体指标问法，
  避免进入新整份报告入口，并为新入口单独增加过滤回归，未覆盖或撤销并行代码。

## 使用与限制

退出旧终端进程后重新启动生效。自由文本的未知姓名、无标签地址和编码变形无法保证完全识别；
仅分析本轮实际读取的数据，不代表已遍历整份报告。真实业务和模型服务未实连验证。
