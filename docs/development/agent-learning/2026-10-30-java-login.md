- 日期：2026-10-30；本记录在用户要求开发留档后补录。
- 范围：`agent-learning/` 的业务登录、HTTP 封装、报告列表和启动流程。
- 状态：登录接入已完成；报告正文及完整问答的真实数据联调未完成。

## 需求与根因

用户启动本地报告助手时看到“本地报告、连接配置或加密历史不可用”。核实当时配置为
`REPORT_DATA_SOURCE=api`，有测试网关地址但缺少 `REPORT_USER_TOKEN`。
原实现只支持手动复用业务 token，没有调用登录接口获取凭证，所以在报告请求之前退出。

用户要求用 Python 对接测试服务，并明确继续调用 Java 已有接口。
本次实现 Python 客户端登录流程，业务用户、验证码校验及 token 签发仍由 Java 负责。

## 最终方案与改动

```text
配置/终端输入手机号
  → 测试通用验证码接口
  → Java H5 登录得到 token
  → 携带 token 获取当前用户报告列表
  → 选择并复核报告
  → 获取报告正文供本地问答
```

| 文件 | 变更及原因 |
|---|---|
| `report_auth.py` | 新增登录封装，支持 test 自动取码和 sms 使用已有验证码，返回 Java token |
| `report_http.py` | 共用网关、HTTP、JSON 与业务成功码检查，错误只返回固定提示 |
| `report_api.py` | 无显式 token 时自动登录；报告为空时明确提示并结束，不等待无效选择 |
| `main.py` | 提示连接和凭证阶段；显示固定业务错误，便于区分登录与本地组件问题 |
| `.env.example` | 补充登录模式、手机号、测试联调标记及可选验证码配置 |
| `README.md` | 记录运行、配置、调用顺序和真实验证边界 |
| `tests/test_auth.py` | 新增 11 项登录、环境限制、凭证隔离和终端空列表路径测试 |

已有显式 `REPORT_USER_TOKEN` 继续优先使用；自动获取的 token 不回写配置。
登录、业务报告和模型分别使用相应客户端，业务凭据不传给模型。
`test` 模式限定测试网关；登录失败不回退为演示报告。

具体协议见 [Java 接口对接说明](../../interfaces/agent-learning/java-business-api.md)。

## 报告选择重复提示排查（2026-10-30）

- 状态：重选提示和进度改善已完成，离线回归通过；尚未复现用户终端“输入序号后无提示、
  直接再次选择”的具体原因，真实报告正文及完整问答仍待验证。
- 现象：用户补充重新显示列表前没有看到错误提示，尚未提供输入序号。
- 已核实：读取失败、输入无效和本地模板校验失败均有固定提示，但随后立即重刷列表，
  提示位于新列表上方；上一页在第一页时原先没有提示。当前 Python 进程呈父子关系，
  仅凭进程数量不能判断为重复启动；未停止或向现有进程注入输入。
- 方案：保留列表复核和正文 ID 校验，把重选原因移到新列表之后、输入框之前，
  增加序号确认、正文读取和模板校验进度并立即刷新输出；接口错误区分列表与正文阶段。
  使用虚构凭据和内存 HTTP 验证有效选择、读取失败重试、模板拒绝、输入错误和翻页。
- 限制：本轮不擅自选择真实报告，不将交互改善视为正文读取或模板适配已经实连通过。

实际变更：`report_api.py` 将重选原因放到刷新后的列表下方，补齐第一页向前翻页提示，
选择后立即刷新进度输出；`main.py` 在正文返回后显示模板校验阶段，把模板失败原因传递给
下一次选择。序号使用 `isdecimal()` 校验，避免 `²` 等 `isdigit()` 接受、但 `int()` 无法解析
的字符导致意外退出。报告列表变为空时仍保留上次读取失败提示，再正常结束。
README 记录新提示和重启方式；接口说明同步固定错误阶段，文档索引更新记录入口说明。
