# 每个模块分析失败的范围与时长校验修复

- 日期：2026-11-17。
- 范围：`agent-learning/` 的整份报告意图识别、逐模块时长来源校验和私有失败诊断。
- 状态：实现及离线回归完成；真实报告复现及实连尚未验证。

## 需求与原因

用户确认此前“分析每个模块”的失败对应本机 2026-11-16 17:26 的唯一诊断：实际执行整份报告分析，在第 2 批第 1 项模块小结触发 `numbers` 类“时长或范围与对应指标来源不一致”。旧记录将 12 条时长校验路径合并为同一标签，且未保存草稿、指标值或报告内容，因此不能判定那次是模型写错还是本地误拦，也不能倒推出具体子原因。

另已核实 `is_report_overview` 未识别这一纯整份报告问法。模型虽可将其路由到 `overview`，一旦失败，`Conversation` 仍按本地未识别范围显示通用未完成提示，无法准确说明整份分析未完成。

使用虚构事实另复现一处明确误拦：同一“案件期间”字段原值和回答均为四位年份区间，原本被复合时长预检当作“持续几年”的区间拒绝。此误拦可独立修复，但不能据此声称它就是上述真实失败的具体原因。

## 方案与改动

- `conversation/questions.py` 将“分析每个模块”“分别解读各个模块”等纯全模块句式完整匹配到整份报告；单个或前几个模块、具体指标及附带其他诉求的句子仍按原范围处理。失败时沿用整份分析未完成提示，不发布局部草稿。
- `security/answer_durations.py` 对同句具名指标、同一引用字段中逐字出现、端点有序的四位年份期间，跳过持续时长的复合区间预检；其后仍由整组数字和来源检查核对。改写端点、跨字段拼接、换指标及真正的持续时长区间继续拒绝。
- `conversation/overview.py`、`integrations/history.py` 和维护脚本将 12 种时长或范围失败路径记录为固定子原因代码。新加密记录使用 v2；读取兼容旧 v1，旧记录不推断子原因。客户回答仍只给未完成提示，诊断不写原异常、模型草稿或报告内容。
- 补充虚构报告、校验和诊断回归；同步 README、本地接口说明及文档索引。Java 接口、模型配置和报告数据未改。

## 使用与限制

### 同日遗漏复查

- 修复整体总结阶段遗漏：已核验小结没有 `name` 字段，原年份放行逻辑只能在模块阶段工作；现在根据该小结原有来源组继承指标名称，并确认同一已展示小结确实含该指标的原样年份区间。不从原报告补入未展示数字。
- 收紧字段绑定：原末尾匹配可能让“其他案件期间”借用“案件期间”；现在消费完整分句的固定前缀、字段名及谓语，跨主体或拼接字段名继续拒绝。
- 修复日志白名单缺口：原布尔判断允许非时长错误携带不在白名单中的任意子原因；现在非时长错误严格要求 `null`，时长错误严格要求固定字符串子码，读写两端一致。
- 补充端到端整体总结复述年份、总结来源不匹配，以及普通错误携带字符串/数字/对象子因的拒绝回归。相关回归：模块总结 56 项、数字校验 45 项、私有诊断 21 项均通过；随后使用 `.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -q` 全量复查 615 项通过，耗时 14.200 秒。差异空白检查通过；真实模型及 Java 报告未调用。

本轮不读取或记录真实报告、模型原始草稿和凭据。旧现场只有固定失败类别、阶段、批次及位置；未来若再次失败，可按新子原因确定校验分支，但仍需对照实际来源排查模型错误或剩余误拦。该修复只处理已复现的年份原文误拦，未放宽统计周期、个人持续时长、来源角色或跨字段借用。修复需重启运行中的客服进程才会生效。
