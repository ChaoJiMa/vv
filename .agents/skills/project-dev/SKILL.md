# 项目开发规范

本技能随项目保存在根目录 `.agents/skills/project-dev/`，由根目录 `AGENTS.md` 引用。
所有路径以项目根目录为基准；当前工作区包含 `agent-learning/` 和 `neighbor-help/`，
开发时先定位目标子项目，保留其他任务已有改动。

## 开发与记录一起完成

1. 读取目标目录适用的规范、README、配置示例及本次功能已有文档；检查分支和工作区状态。
2. 明确本次预期行为、改动范围和验收方式。缺陷先定位根因，接口先核对实际调用与后端契约。
3. 在 `docs/development/<子项目>/YYYY-MM-DD-<主题>.md` 建立或更新本次记录，写明需求、原因及拟定方案。
   同一需求继续开发时更新原记录，不按每轮聊天重复建文件；小范围连续注释修改可合并记录。
4. 完成已授权的实现及中文注释，同步更新受影响的接口文档、配置示例和使用说明。
5. 执行与本次改动匹配的验证，把命令、结果和未验证范围写回记录；在 `docs/README.md` 维护入口。
   纯记录补充直接更新对应记录，不为“记录文档的更新”递归新建记录。

记录格式及文档归档规则见 [references/records.md](references/records.md)，创建记录前阅读。
普通改动不增加强制评审等待；需要补充的信息先从现有代码和上下文获取，避免重复确认已授权范围。

## 代码与注释

- 沿用目标子项目的架构、命名、接口包装和依赖，不为应用本技能升级框架或重构无关模块。
- 新增或实质修改的模块、类和关键方法使用中文说明职责、关键输入、返回值、异常和调用顺序。
  按方法复杂度展开，不必为每个简单取值方法重复一套空泛标签。
- 在分支和协议边界解释“为什么”：参数位置、状态含义、权限来源、数据缺失语义、资源释放及回退条件。
  重要常量注明业务意义，示例使用虚构数据，不把密钥、token、真实验证码或个人报告写入注释。
- 注释与实际行为一致。修改逻辑时同步修改注释；只改注释时检查业务代码结构没有变化。
- 用户明确的架构选择属于当前约束。报告助手继续复用 Java 登录和报告接口，不自行替换为 Python 身份系统。
  修改 `agent-learning/` 时再阅读 [references/report-assistant.md](references/report-assistant.md)。

## 接口与配置文档

- 接口新增、参数调整、鉴权变化或调用顺序变化时，更新 `docs/interfaces/<子项目>/` 下对应说明。
  写明 HTTP 方法、服务前缀、参数所在位置、响应成功条件、调用方实际依赖的字段和异常处理。
- 区分“Java 已有接口”“Python 调用封装”“本地工具”，不能把客户端封装写成新增后端接口。
- 配置文档只记录变量名、作用、默认行为、必填条件和安全示例；真实值留在被忽略的本机配置中。
- 本地假数据、内存 HTTP 测试、测试服务实连分别记录。HTTP 200、业务成功、报告有数据和完整问答成功是不同结论。

## 验证与交付

- 先核对现有验证入口，优先使用已安装工具和相关检查；是否新增测试依据实际风险和项目约定。
  纯注释或文档变更通常检查语法、链接、结构及相关既有测试即可，不创建只核对文案的测试套件。
- 未运行、失败、没有数据而无法覆盖的场景均如实记录，不把上一轮检查当成本轮重新执行。
  使用历史验证证据时注明来源日期与适用范围。
- 交付时说明完成行为、验证结果、文档路径及实际限制。未完成必要开发记录时，不把开发标记为完整交付。
- 技能本身不授予推送、合并、部署或其他外部写入权限，这些操作仍遵循用户现有授权。
