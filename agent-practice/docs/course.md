# Python 到 Agent 应用：完整课程

本课程面向有前端开发经验、希望转岗求职并独立完成 Agent 应用的学习者。D1–D56 是**课程编号**，不是自然日、提交次数或已掌握证明；每天可用 2–4 小时且可能被工作打断时，一个编号可以跨多次学习，多个已掌握编号也可以合并验收。**当前 D1 的原 8 题核心已验收，交互式项目任务尚未完成，D1 整体未通过，D2–D56 也未验收。**[当前任务](current-plan.md) 和 [实际进度](../progress.json) 决定下一步。[原路线](roadmap.md) 提供主题索引，本文件提供每课要做的事与可检验的结果。

## 怎样使用这套课程

1. 开始一次学习前，查看当前计划，先花约 5–10 分钟回忆上次卡点；新语法先读本阶段讲解，再参考项目中当天题目文件的说明。每段学习控制在约 25–40 分钟，可随时中断，不靠时长判定通过。
2. 以同一个“AI 任务助手”逐步扩展：先实现任务数据处理，再做命令行、API、前端、模型、工具和可靠性。每课只要求一个明确的项目增量和至少一个边界用例，不机械重复若干道同类输出题。
3. 当天的具体题目应在对应练习文件中给出：前置讲解、输入数据、目标行为、验收用例、代码区和作答注释区放在**同一文件**。本课程是完整教学蓝图；将来展开 D2–D56 时先检查目标文件是否已有用户代码，保留原作答，不预填完整答案。D1 的 `task_info.py` 已有用户写下的 `input()`、`strip()`、`int()` 代码，后续提示或验收不得覆盖这些行。
4. 完成后可以直接说“检查当前课”。助手读取本地代码与注释，安全地运行正常和边界用例，说明已验证的行为、真实卡点及下一次安排，并更新进度与反馈记录。仅提供口头“做完了”时先核对代码，脚本能启动不等于通过。模型实连、部署和产生写入的检查要与模拟结果分开记录。
5. 每阶段最后一课做独立改需求、异常用例和约 3 分钟口述：说清输入、关键设计、实测结果和限制。遇到不会的前置能力只补该点；通过新数据变式且能解释时可合并相邻课。免做的内容要记录依据，不把跳过写成完成。

每课表中的“正常 / 边界”是最低验收用例，讲义展开时还需写明具体输入、预期输出或状态，以及失败时的可观察结果。输入示例用虚构任务，不使用真实报告、密钥或个人资料。面试表达题按阶段给出，平时可用正在写的代码回答，无需背定义。涉及协议字段、鉴权、落库结果的要求严格验收；显示空格和非核心措辞只作为改进建议。

## 阶段 1：Python 数据与流程（D1–D7）

**前置与讲解。** 具备 JS/TS 基础即可，从 Python 解释器、赋值、`str/int/float/bool`、`print()` 开始。JS `const title = "读书"` 对应 Python `title = "读书"`；JS 模板字符串对应 Python f-string；JS 的 `Number(text)` 对应本阶段受控数字输入上的 `int(text)`。`input()` 返回字符串，`bool("n")` 仍为 `True`；`if` 用冒号与缩进。接着用列表对应 JS 数组、字典对应对象，练索引、缺省值与循环。将“修改变量后旧计算是否自动变化”用新数据复测。

**逐课学习抓手。** D1 先画出输入字符串→类型转换→分支→输出的执行顺序，再运行未见过的输入；D2 对照数值相加和字符串拼接，先预测输出再运行；D3 用完成状态和时间差列出分支表，特别检查“刚好相等”；D4 画列表索引与长度关系，先判断空列表能否取首项；D5 对比 JS 对象属性与 Python 字典键，辨别“键缺失”和“值为假”；D6 每轮手算计数器和累加值，再与循环输出核对；D7 换一组陌生任务独立改筛选条件，口述一次错误的发生路径。

**阶段产物与验收。** 任务展示器 v0.1 能接收或存放若干任务，展示、筛选并统计数量和预计时长。给一组未见过的数据独立修改展示规则，空列表与缺字段可解释。面试表达：`"40"`、`40`、`40.0` 在转换、比较和打印时有什么不同？为什么赋值后的旧结果不会自动重算？

## 阶段 2：函数、模块与持久化（D8–D14）

**前置与讲解。** 已能用列表、字典和循环处理任务，再将代码拆成函数。JS `function f(x) { return x }` 对应 Python `def f(x): return x`，`print` 负责显示，`return` 把结果交回调用方；类型标注说明意图，普通 Python 并不会仅凭标注自动拦截所有运行时错误。学习默认参数时检查可变对象共享；用 `python -m venv` 理解隔离，再接 `pathlib`、`with`、JSON、异常和最小测试。依赖按实际课需要安装，本课程不自动安装。

**逐课学习抓手。** D8 先写调用者需要什么返回值，再决定函数职责；D9 连续调用同一函数两次，观察默认参数是否泄漏前次状态；D10 从入口执行和从别处 `import` 各试一次，确认入口保护；D11 手工检查 JSON 文件编码和保存后的重启结果；D12 从 traceback 最后一层往回定位异常，再区分用户输入错误与文件损坏；D13 把一轮菜单操作拆成可单独断言的函数行为；D14 不看旧搜索实现先列输入与输出，再独立加入功能。

**阶段产物与验收。** 命令行待办 v0.2 支持添加、展示、完成、删除、标题搜索，重启后从 JSON 恢复。核心计算写为可直接调用的函数；正常、空输入、损坏文件各有结果。面试表达：为什么文件读写要与任务筛选分开？`print` 和 `return` 的差别怎样影响测试？

**快进规则。** 能独立将 D7 逻辑重构为函数、通过新数据断言时，合并 D8–D10 的基础语法课，仍需实际验证默认参数、导入路径和文件恢复；已有 JS 函数经验不替代 Python 可变默认值测试。

## 阶段 3：HTTP、FastAPI 与 SQLite（D15–D21）

**前置与讲解。** 命令行任务操作和 JSON 持久化通过后，再把同一业务搬到 HTTP 服务。前端 `fetch('/tasks')` 发出请求，Python 路由接收方法、路径、查询参数和 JSON 请求体；返回值须同时检查 HTTP 状态、响应结构与数据库变化。FastAPI 用类型标注和请求模型表达接口边界，业务规则仍由自己写。SQLite 先用参数绑定完成 CRUD，再理解主键、索引、事务和一次简单关联查询。首次引入第三方库时，先建立环境并按当时官方说明确认依赖版本。

**逐课学习抓手。** D15 对一个浏览器请求画方法、路径、状态码、响应体四格；D16 先辨别资源 id 与过滤条件，再试不存在的资源；D17 按字段逐个判断类型校验与业务校验归谁负责；D18 用同一 id 依次增、查、改、删，观察每次状态；D19 对比字符串拼接 SQL 和参数绑定在单引号输入上的行为；D20 先预测提交与回滚后数据库内容，再制造失败核对；D21 从一条接口用例追踪路由、业务、存储三层，并用小型虚构表手推 JOIN。

**阶段产物与验收。** 任务 API v0.3 提供查询、创建、修改、删除与 SQLite 持久化；至少覆盖每个操作的正常与失败路径。面试表达：请求体校验与业务规则为什么都需要？一次请求从路由到数据库如何经过各层？参数化 SQL 解决什么问题？

**快进规则。** 熟悉 HTTP 概念可快速做 D15–D17 的接口诊断，若能独立改一个请求字段并给出错误响应，可合并讲解；SQLite 事务、数据持久化和测试仍按实际结果验收。

## 阶段 4：全栈联调与异步边界（D22–D28）

**前置与讲解。** 复用用户熟悉的 Vue 或 React 页面，不重复上完整前端入门课。JS `await fetch(...)` 与 Python `await` 都表示等待异步工作，但同步数据库函数、阻塞 HTTP 客户端和 CPU 计算不能因为写了 `async` 就变成非阻塞；先理解本项目调用链，再决定何处需要异步。前端请求要分清网络失败、HTTP 失败、业务失败，页面状态要与服务器真实结果一致。

**逐课学习抓手。** D22 在浏览器网络面板核对请求 URL、响应状态与页面三态；D23 对一次写入先预测服务器成功与失败时页面各该怎样变化；D24 快速连点制造重复请求，观察按钮和数据库；D25 画出路由→业务→存储调用图，确定错误在哪层记录；D26 对照 JS Promise，区分等待 I/O 和占用 CPU 的代码；D27 从空终端按文档启动，记录第一处失败并修复；D28 先列优先级字段在表、请求、响应、页面和旧数据中的位置，再逐层修改。

**阶段产物与验收。** 全栈待办 v0.4 从页面完成任务增删改查，并能独立把“优先级”字段贯穿数据库、接口、页面和测试。面试表达：一次页面提交失败后，为什么不能直接显示成功？增加字段时要核查哪些层？Python 的异步适用于什么等待？

**快进规则。** 先用一个真实联调任务诊断已有前端能力；若页面状态与请求处理已熟练，可合并 D22–D24，把时间用于 Python 存储、异步和跨层变更。D28 的独立字段变更不可省略。

| D27 集成修复与启动说明 | 按另一位开发者的视角整理启动步骤，修复一次真实联调问题。 | 正常：根据 README 启动服务和页面后可完成一次任务；边界：接口返回错误时页面给可操作反馈。 |

## 阶段 5：模型调用、多轮聊天与结构化结果（D29–D35）

**前置与讲解。** 全栈任务基础通过后，再将模型加入现有应用。区分用户消息、模型回复和服务器自己执行的业务代码；模型说“已创建”不能代替数据库写入。把厂商调用包在服务层，密钥只在服务端环境中；失败、超时、无效结构化结果要可检查。多轮聊天至少区分两个会话，控制传入的历史长度，并从第一天起保存小规模固定输入、预期行为和实测结果。离线固定响应与真实模型调用分别标明。

**逐课学习抓手。** D29 对照一轮消息的请求和回复，标出用户文字与服务端配置；D30 先列成功、超时、凭据错误三种返回，再封装调用；D31 用两个 `session_id` 交错发消息，手算各自历史；D32 在发送中和失败时检查界面是否出现虚假回复；D33 把模型输出当外部输入再校验，区分草稿与已写入任务；D34 对固定输入先写预期再运行，并同时记耗时和实际业务状态；D35 随机抽一条历史和一条坏输出解释处理链。

**阶段产物与验收。** AI 聊天应用 v0.5 支持多轮对话、任务草稿提取和错误提示，尚不自动执行写入。面试表达：模型的文字回答与工具执行事实有什么区别？怎样知道一次结构化提取是可靠的？上下文增长影响什么？

**快进规则。** 若用户已有模型 API 使用经验，可用同一组正常/超时/格式异常输入完成 D29–D30 诊断；会话隔离、草稿校验和虚假成功防护仍需真实代码或明确标记的模拟证据。具体 SDK 与模型名称按开发时官方资料和环境选择，不锁死在本课程文本中。

| 课 / 核心 | 同一项目的具体任务 | 正常 / 边界验收 |
| --- | --- | --- |
| D29 模型请求与消息 | 从服务端读取配置，做单轮调用脚本或明确标记的离线响应。 | 正常：用户输入得到一条可展示回复；边界：无密钥时走明确的模拟路径或给配置提示，不在前端暴露密钥。 |
| D30 模型服务封装 | 统一模型调用的入参、超时、错误分类和业务层返回。 | 正常：模型服务返回文本供上层使用；边界：超时或无效凭据返回明确失败，不伪造正常回答。 |
| D31 聊天接口与会话 | 提供 `POST /chat`，用 `session_id` 区分历史，保存必要消息。 | 正常：同一会话追问能使用先前任务语境；边界：另一个会话不见到前一会话的消息。 |
| D32 聊天页面 | 前端发送消息并展示回复、发送中与失败状态，定义刷新后的历史行为。 | 正常：连续两轮显示对应问答；边界：发送失败不会留下冒充模型回复的空消息。 |
| D33 任务草稿与校验 | 从自然语言提取任务标题和可选日期，校验结构后只显示草稿。 | 正常：“明天写周报”得到可核对草稿；边界：缺标题或字段类型不对时请求补充，不创建任务。 |
| D34 固定用例与成本 | 建 10 条正常、模糊、无关输入用例，记录预期、实际、耗时及可用时的用量。 | 正常：同一固定输入有可比较结果；边界：模型回答“已创建”但未执行工具时记录为未创建，不计业务成功。 |
| D35 阶段验收 | 演示两个会话的聊天和一项任务草稿，解释模型层与任务业务层的职责。 | 正常：一会话的追问连贯且草稿字段可验证；边界：另一个会话隔离、坏输出给提示，并标明模拟或实连。 |

## 阶段 6：工具调用与有限 Agent（D36–D42）

**前置与讲解。** 先做不依赖模型的 Python 工具调度，再把经过校验的模型工具请求接进来。JS 对象中保存函数引用与 Python 字典保存可调用函数类似；函数名、参数结构和权限必须走明确白名单，不能让模型生成任意 Python 代码执行。模型提出操作意图，服务端按真实数据和权限执行；写入先呈现目标与参数，收到用户确认后才落库，确认要绑定具体草稿。有限循环必须有最大步骤、停止原因和执行轨迹。

**逐课学习抓手。** D36 从函数引用和字典查找开始，先在纯 Python 中走通调度；D37 对每个工具写明允许参数，再用未知名称和错误类型反测；D38 把模型提出的工具名、真实执行结果和最终答复排成三列比较；D39 用拒绝、确认、重复确认三次动作观察数据库；D40 先创建两个同名任务，再设计按 id 澄清；D41 为每次循环记步骤编号、调用、结果和停止原因；D42 从固定用例抽一条失败轨迹说明为何未写入。

**阶段产物与验收。** 任务 Agent v0.6 可查询、创建、修改、删除任务，区分只读与写入，并处理同名任务歧义、拒绝确认和工具错误。面试表达：为什么工具调用结果必须回传模型？确认为什么要绑定参数？有限 Agent 与固定工作流的差别是什么？

**快进规则。** 理解前端事件分发可减少“函数作为值”的练习量，但 D37–D42 的白名单、参数校验、写入确认与失败轨迹必须逐项有证据。若一次模型调用加明确的业务函数已满足场景，应能说明为何暂不引入多步骤循环。

| 课 / 核心 | 同一项目的具体任务 | 正常 / 边界验收 |
| --- | --- | --- |
| D36 纯 Python 调度 | 用函数引用和字典映射按名称调用 `list_tasks` 等本地函数，记录返回结果。 | 正常：已知名称与参数调用到正确函数；边界：未知名称被拒绝，不用 `eval` 执行字符串。 |
| D37 工具描述与参数 | 为查询、创建、更新定义名称、参数结构和白名单，先本地校验。 | 正常：合法 `create_task` 参数形成可检查调用；边界：多余或类型错误的字段被拒绝，不触发写入。 |
| D38 只读工具闭环 | 让模型请求 `list_tasks`，服务端执行并把实际结果回传以形成回答。 | 正常：查询回答与当前任务数据一致；边界：空列表或工具失败时明确说明，不凭模型想象补任务。 |
| D39 创建与确认 | 自然语言先生成任务草稿，用户确认同一草稿参数后才入库，加入最小重复确认保护。 | 正常：确认一次仅新增一项；边界：拒绝不写入，同一确认重复发送也不新增第二项。 |
| D40 修改、删除与歧义 | 对已有任务按 id 操作；同名时先给候选目标，删除前展示影响并确认。 | 正常：指定目标的标题被修改；边界：两个同名任务未明确 id 时不误改或误删。 |
| D41 有限步骤循环 | 支持查询后再操作的两步流程，记录每步工具、结果、错误与停止原因。 | 正常：查询得到 id 后按确认修改；边界：达到最大步数或工具报错时停止，保留可复核轨迹。 |
| D42 阶段验收 | 用至少 12 条查询、创建、修改、歧义、拒绝和错误用例复测工具闭环。 | 正常：确认后的目标操作与数据库一致；边界：未确认写入、错误目标和超步数用例必须不产生错误写入。 |

## 阶段 7：检索分支与运行可靠性（D43–D49）

**前置与讲解。** D42 的工具闭环通过后，D43–D44 选一条岗位相关分支：A 用 8–10 份虚构资料做关键词检索、引用和无答案处理；B 做流式事件、前端片段拼接和状态展示。JS `AbortController` 可停止浏览器等待，但不能据此断言服务端任务已取消，Python 服务端还须处理取消、超时和资源清理。对写入请求，超时后的实际数据库状态需要查询；重试携带稳定 `operation_id`，避免创建两次。评估同时核对回复、工具轨迹和最终数据。A 的关键词检索是可解释基线，若目标岗位要求向量检索，再追加分块、嵌入和召回比较；不要把两者混称。

**逐课学习抓手。** D43 先按岗位选 A 或 B，并给资料片段或事件写最小数据结构；D44 对 A 逐句核对来源、对 B 逐事件核对页面状态；D45 用取消发生在请求前、响应中、写入后这三个时点画状态图；D46 对照内存会话与落库会话的重启行为；D47 把同一 `operation_id` 连发两次并查询数据库；D48 先给 20 条输入写预期，再分别记录回答和最终状态；D49 选择一个失败案例复现、修复、重跑。

**阶段产物与验收。** 可靠性版 v0.7 有可恢复会话、取消与超时反馈、写入幂等、20 条固定中文用例，并完成所选分支的实际演示。面试表达：用户点取消后怎样确认写入是否发生？关键词与向量检索各有什么限制？一次 Agent 评估为什么要查最终数据库？

**快进规则。** 根据目标岗位和当前困难只选 A 或 B；未选分支保留为后续选修，不标记完成。若有现成流式经验，可压缩 B，但必须实测断连、工具状态和错误事件。D45–D49 的取消、持久化、幂等及评估均不能由界面演示代替。

| 课 / 核心 | 同一项目的具体任务 | 正常 / 边界验收 |
| --- | --- | --- |
| D43 A 检索 / B 流式协议 | A：为 8–10 份虚构资料做关键词检索，返回片段与来源；B：后端输出文本、工具、结束、错误四类事件。 | 正常：A 的固定问题命中预期片段 / B 事件按顺序到达；边界：A 无命中返回空 / B 中途失败发错误事件并结束。 |
| D44 A 引用 / B 流式页面 | A：把检索结果接为只读工具，回答附实际来源；B：前端拼接文本并显示工具运行状态。 | 正常：A 能核对引用片段 / B 完整回复和最终状态一致；边界：A 无依据时说明不知道、资料内指令不触发写入 / B 断流时不显示成功。 |
| D45 取消与超时 | 给聊天请求增加取消入口和服务端超时，记录客户端停止、服务端结束和写入结果。 | 正常：取消后旧回复不再写入当前会话界面；边界：请求已触发写入时不能仅凭前端取消宣称未写入，必须查询结果。 |
| D46 会话持久化 | 将会话、消息和关键工具轨迹保存到数据库，给历史长度设上限。 | 正常：重启后同一会话可恢复历史；边界：不同会话不串内容，超长历史按规则截取而非无限发送。 |
| D47 重试与幂等 | 对创建操作保存 `operation_id` 和处理结果，区分只读重试与写入重试。 | 正常：相同编号重试返回同一任务结果；边界：网络超时后重复提交不产生第二项，编号相同但参数变化被拒绝。 |
| D48 固定评估集 | 建 20 条中文用例，覆盖查询、歧义、确认、工具失败、重复请求和所选分支。 | 正常：逐条记录输入、预期、实际回复及最终任务状态；边界：模型声称成功但工具失败时判为失败，不能只按措辞评分。 |
| D49 阶段验收 | 重跑固定集、修复优先级最高的真实失败，演示一次取消与一次重复确认。 | 正常：关键写入保护和所选分支用例通过；边界：未修复用例列出失败原因，不把未运行或模拟项记作通过。 |

## 阶段 8：权限、部署与求职展示（D50–D56）

**前置与讲解。** D49 的稳定性证据足够后，给多用户数据加服务端身份和归属判断。前端隐藏按钮只改变界面；API 路由与 Agent 工具执行处都要验证当前用户是否有权访问目标任务。部署时用环境变量、可重复的依赖安装、健康检查和持久化数据目录，重启后重新验证业务。JS 前端的端到端测试思路可以迁移到 Python API、数据库与模型替身，但真实模型演示和模拟回归要分开标注。求职展示用具体输入、调用轨迹、数据库结果和失败修复说明能力，不编造生产规模。

**逐课学习抓手。** D50 先创建 A、B 两个身份和各自任务，再从服务端过滤归属；D51 分别从直接 API 与 Agent 工具尝试跨账户 id；D52 在干净环境按文档构建，记录每项必需配置；D53 重启后查任务与会话，并故意让模型服务失败；D54 让端到端用例经过页面、API、数据库真实调用链；D55 用一个成功案例和一个故障修复案例练 3 分钟介绍；D56 先写新工具的输入、权限、确认和测试，再独立实现并接受追问。

**阶段产物与验收。** AI 任务助手 v1.0 具备任务归属、直接 API 与工具权限、可重复启动、回归报告、项目说明和 3 分钟演示。面试表达：给定另一用户的任务 id，你在哪里拦截越权？重启后如何判断系统真的可用？若模型选错工具，你怎样定位并改进？

**快进规则。** 有现成容器与部署经验可压缩命令讲解，但必须在干净环境复现启动、数据保留和健康检查。已有前端端到端测试经验可沿用工具，D50–D51 的跨账户服务端权限与 D56 的独立扩展仍需实际证据。部署目标由当前环境与权限决定，能重复演示的本地容器也可验收，不强制购买云服务。

| 课 / 核心 | 同一项目的具体任务 | 正常 / 边界验收 |
| --- | --- | --- |
| D50 身份与任务归属 | 给演示账户、任务 `owner_id` 和 API 的服务端身份判断建最小闭环。 | 正常：用户 A 登录后只读写自己的任务；边界：无凭据或使用 B 的任务 id 时被拒绝，B 的数据不变。 |
| D51 工具权限与敏感信息 | 把同一归属校验接到 Agent 工具，复测直接 API 和自然语言路径，清理日志中的敏感值。 | 正常：A 的合法工具请求成功；边界：A 借工具查询、修改或删除 B 的任务均失败，日志不包含密钥。 |
| D52 可重复构建 | 固定依赖和配置说明，提供容器或等效部署包，设置健康检查与持久化目录。 | 正常：按说明从干净环境构建并启动；边界：缺关键配置时明确报错，重建镜像不意外清空数据目录。 |
| D53 运行演练 | 在自有环境或本地容器运行服务，完成页面、API、Agent 一次完整任务流程并重启。 | 正常：重启后任务和会话仍可查；边界：模型服务不可用时普通任务功能和错误提示可用，不显示假回复。 |
| D54 端到端回归 | 写登录、建任务、自然语言查询和确认修改的端到端用例，演练一条错误路径。 | 正常：主路径在新启动实例上通过；边界：越权、错误参数或工具失败至少一项有自动或可复现的失败断言。 |
| D55 文档与演示 | 完成项目 README、架构和接口说明，录入 3 分钟项目介绍与 10 分钟技术追问要点。 | 正常：他人按说明运行并看到可核实的演示数据；边界：未做真实部署或模型实连时明确说明范围，不编造用户量和性能。 |
| D56 独立扩展与模拟面试 | 不看完整答案新增一项只读或写入工具，补权限、确认与回归，复盘 Python、SQL、异步、Agent 问题。 | 正常：新工具从请求到实际任务状态可演示，原关键用例仍通过；边界：无权限、歧义目标或重复请求不造成错误写入，未掌握项如实列出。 |

## 最终作品与复盘证据

作品至少可展示任务 API、数据库、页面、模型草稿、受控工具和评估记录。每项能力保存一份可重跑证据：输入、预期、执行步骤、实际响应、数据状态及限制。项目介绍按“用户问题 → 架构与职责 → 一次正常调用 → 一次失败修复 → 取舍”组织；模拟问答覆盖 Python 可变对象、异常、SQL 参数绑定与事务、HTTP 校验、异步等待、工具权限和评估。完成 D56 后对照目标岗位招聘要求逐项补缺，不以课程编号替代岗位录用标准。
