前置能力未通过则补练；已有能力经诊断后可合并主题。实际下一步见 [当前计划](current-plan.md)，每次调整按 [反馈规则](feedback.md) 记录。

## 调整重点

1. Python 基础保留，但不机械刷同类题。重点掌握前端迁移时容易出错的赋值与引用、可变对象、作用域、异常、类型标注和异步。
2. D8 起穿插函数断言、类型标注；D10 讲虚拟环境和解释器；D11 结合 `with` 与 `pathlib`；D12–D13 开始读错误和写小测试。首次安装第三方库前再核对环境，不自动安装。
3. 前端界面复用熟悉的栈，D22–D28 可经验证压缩，投入保留给 Python、SQL、调试、模型和工具。完整跨层字段变更仍需独立完成。
4. 通过 D14 的函数/JSON 验收后，可加一次 15–20 分钟的“模型输出与代码执行有什么区别”演示；无密钥用明确标注的固定假响应。演示不算掌握模型 API，也不要求提前学完整框架。
5. 模型和工具阶段从第一条路径就保存输入、预期、实际结果和失败原因；创建工具首次落库时先做最小重复确认保护，D47 再深入持久化幂等与重试。
6. 为求职提供 RAG 实践分支：先检索一小组虚构资料，验证引用和无答案行为，再按岗位需要加入向量检索。替换部分可选流式展示时间，不将它全部叠加到原任务上。
7. 每次学习练一次已学内容的简短解释；每阶段独立修改一个需求、修复一个问题，并讲清设计取舍。积累面试素材，不能仅凭应用可运行认定能独立面试。

## 求职分支与下一阶段

优先交付一个能独立解释、修改、验证的项目。具体招聘要求尚未提供，以下是补齐能力的选择，不代表所有岗位都要求同一套技术。

- Agent 应用方向：先完成工具闭环与评估，再按目标岗位选择 D43–D44 的检索分支；进一步比较关键词与向量召回、分块、引用、无答案和资料更新。关键词版本只是基线，不冒充向量数据库经验。
- Python 后端方向：保留 SQL、事务、索引、异常、测试、异步和权限的独立练习；需要时增加连接管理和并发场景，不以只会调用模型 API 代替后端能力。
- AI 全栈方向：界面复用已有能力，强调流式/取消、错误恢复、鉴权和端到端排错；先选择一个 D43–D44 分支，另一个之后补，不同时堆满。
- MCP、Agent 框架和多 Agent：工具调度与评估通过后，再根据目标岗位选一个协议或框架做最小接入，说明它解决什么问题；不作为当前 Python 入门的前置。

每阶段验收产出一小段“问题—设计—实测—限制”的口述材料和一项独立变更。若用户提供目标岗位描述，后续反馈对照要求补缺口，并说明哪些内容延后。
