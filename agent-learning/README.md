# 信用报告查询与规则解释助手

开启外部模型后，由 AI 理解问题、按需读取当前报告并组织分析；程序负责权限、个人信息过滤与输出检查。当前是单用户终端原型，默认完全本地运行。

项目级规范位于根目录 [AGENTS.md](../AGENTS.md) 与
[project-dev skill](../.agents/skills/project-dev/SKILL.md)。开发记录及 Java 接口说明见
[项目文档索引](../docs/README.md)，后续开发同步维护。

## 客服持续模拟评测

客服共同规则保存在 `report_customer_rules.py`，由具体指标、模块小结和整体总结共用。
只回答页面已确认的结果；不解释底层值、编码和计算过程，不把缺失当零，
不混用次数、机构数和周期，不承诺贷款、退款或已经接通人工。
区间及“以上/以下”保留范围含义：既不确认范围内的某个精确值，也不排除它的可能性。
优先解释已确认内容；次要字段无法确认时，不把整个模块写成无法解读，
不逐模块重复“请在报告页面核对”。真正需要补充资料时，只给一次具体的下一步。
简单问题默认一句，必要时才补解释；不反问确认明确问题、不额外附信用评价或泛泛邀问。
学历、婚姻、手机在网等模块只解释自身结果，整体情况放在末尾总结。

## 数据如何流动

1. 完整常见客服短句先在本地回复；不会把问候后的复合问题截断。其余问题检查姓名、证件、手机号、地址及凭据，可疑问题整轮保留在本地，不调用模型协助脱敏。婚姻、学历、案件编号及其他普通报告文字不再一律拦截；`/find`、`/pick` 仍在本地执行。
2. “分析下我的报告”“按模块总结我的报告”等完整整份报告问法直接进入模块总结；其他通过检查的自然问题发送给 AI 判断属于整份报告、具体问题、客服还是范围外问题。路由输入只含当前问题及“是否有上一报告上下文”的布尔状态，便于识别“那银行呢”等短追问，不含旧问题、字段引用、报告目录、数值或完整历史。客服只选封闭主题，由本地提供固定说明；范围外问题返回既定服务范围文案。
3. 整份报告从当前模板的第一个模块开始，按实际顺序读取每个模块已登记且可解读的全部内容，分批生成简短小结，最后另做整体总结；不抽样冒充全量分析，不逐字段输出或附字段依据清单。没有可解读内容的模块保留位置并说明。具体指标问题仍由 AI 自主列模块、分页列字段、选择必要事实。工具只接受会话内引用，不接受业务用户、报告 ID、路径或 SQL。
4. 报告业务内容先排除姓名、证件、手机号和地址，再按本地已核实的页面规则提供展示结果；学历等枚举给实际文字，档位给展示档位，区间不反推具体数值。未知显示规则不以原值冒充页面结果。文字、案件明细、业务编号、布尔、数组和对象按同样规则及四类个人信息过滤处理。登录token、验证码、密码和模型密钥不进入报告模型消息。具体问答每轮最多7次请求、12次工具调用、48个不同字段。
5. 具体指标问答先给结果，再说明必要含义；不显示底层值、隐藏编码、计算过程、字段编号或统一免责声明。问分数只给当前页面展示分数和已确认等级。整份报告显示“模块标题＋一段概括”，结尾综合主要情况与关注方向，每段最多450字。程序仍核对引用和数字；不合规输出、服务失败或超限时回到本地查询，不显示部分模块小结或转发异常正文。
6. 完整问答只进入本地加密历史。模型追问上下文最多保留通过检查的上一报告问题及字段引用，不保留完整答案、工具结果或思维链；仅当 AI 判断为指代追问时补入。切换报告、通用问答或重启会清空该上下文。历史保存成功后才提交内存状态。

外发自然问题与脱敏报告内容意味着数据离开本机，并非完整匿名化。已知值及格式检查不能保证识别所有未标注的陌生姓名、地址或变形编码，请勿在问题中粘贴个人信息。代码没有取得服务商零留存或不训练承诺；引用和数字检查也不能完全验证自然语言推理。分析用于解释所读事实，不推断审批结果或授信概率。

本地显示器已补齐非银其他申请的组合统计与档位、记录时间文字、婚姻登记、手机在网时长、收入预测、部分借贷图示与金额区间、案件编号候选合并等规则。组合依赖及查询状态码只在本地使用；Java已经转换的值不二次解码。未知规则仅在确有值时标为无法确认，原本缺失、null和空白保持区分；未知图示编码仍不猜含义。规则与字段目录记录的固定页面源码版本核对，不能据此保证线上页面所有版本均一致。

上述7次请求、12次工具调用、48个字段的预算适用于具体指标问答。整份报告独立限制为96个模块、4096个字段、每模块256个字段；每批最多8个模块、256个字段，问题与批次JSON合计不超过100000字符，最多32批再加1次整体总结，语义路由最多另加1次。超过上限整轮回退，不静默截断。模块与整体总结请求均为8192 tokens、90秒超时；报告模块较多时耗时和用量会增加。

每份报告独立匹配版本和启用模块。总结覆盖当前模板中已登记且允许解读的内容，不代表所有原始明细均已开放；四类个人信息仍通过本地检索查看。底层 Python `Conversation` 默认参数保留旧 `template` 协议供兼容调用；终端入口明确使用 `analysis` 策略，开启外部模型后即生效。

## 运行

```powershell
cd D:\vv\agent-learning
.\.venv\Scripts\python.exe main.py
```

在当前运行窗口输入问题并按回车发送；使用PyCharm时，请在运行`main.py`的运行控制台内输入。
发送后立即显示“已收到”，处理期间每10秒刷新等待提示，完整答案在校验与加密历史保存成功后显示。
若尚未出现接收提示，先核对输入窗口和是否按回车；再次出现问题输入提示表示已经等待下一轮输入。
等待时间不代表完成比例；整份报告需要逐批分析，90秒超时是单次模型请求的预算，并非整轮耗时上限。
网络超时或模型失败仍按原规则给出原因并回退本地查询。按Ctrl+C可退出；提示线程也会结束。
如果已经出现下一次“请输入问题”，可输入`/history`回看当前报告最近已保存的回答。
本次终端反馈改动需退出正在运行的助手并重新启动才能生效。

首次安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

启动时读取本地 `.env`，当前终端的同名环境变量优先。建议先保持：

```dotenv
REPORT_DATA_SOURCE=demo
REPORT_EXTERNAL_MODEL=off
```

`off` 模式不需要模型密钥，也不会创建模型客户端。开启 AI 时，设置 `REPORT_EXTERNAL_MODEL=on`，再按下表选择厂商；默认仍为智谱。配置只在启动时读取，修改后退出旧进程并重启；终端的同名环境变量优先于 `.env`。启动提示会显示实际厂商、型号及报告内容外发范围。业务接口和模型分别使用独立 HTTP 客户端，不共享业务 token，关闭环境代理和自动重定向；模型请求关闭自动重试，失败仅回退本地，不自动转给另一厂商。

| `REPORT_MODEL_PROVIDER` | 密钥配置 | 型号配置及默认值 | 模型出口 |
|---|---|---|---|
| `zhipu`（默认） | `ZHIPU_API_KEY` | `ZHIPU_MODEL=glm-5.3-flash` | 智谱标准 API |
| `deepseek` | `DEEPSEEK_API_KEY` | `DEEPSEEK_MODEL=deepseek-flash` | DeepSeek 官方 API |
| `openai` | `OPENAI_API_KEY` | `OPENAI_MODEL=gpt-6.1-sol` | 默认官方Responses API，可用 `OPENAI_BASE_URL` 指定兼容网关 |

例如在本机被 Git 忽略的 `.env` 中设置：

```dotenv
REPORT_EXTERNAL_MODEL=on
REPORT_MODEL_PROVIDER=deepseek
DEEPSEEK_API_KEY=填写自己的模型密钥
DEEPSEEK_MODEL=deepseek-flash
```

真实密钥只保存在本机 `.env`，不要提交到代码或填写到 `.env.example`。智谱与DeepSeek出口固定；OpenAI允许操作者显式配置 `OPENAI_BASE_URL`，未设置或留空使用官方地址，不读取 `ZAI_BASE_URL`。DeepSeek使用OpenAI SDK的兼容协议，明确关闭思考，具体指标请求最多1800 tokens、30秒超时，模块与整体总结请求使用8192 tokens、90秒；支持工具调用与JSON路由，适配器不回传思维链。具体接口和验证边界见 [模型接入说明](../docs/interfaces/agent-learning/model-providers.md) 与 [模型开发记录](../docs/development/agent-learning/2026-10-31-deepseek-provider.md)。

使用 GPT-6.1 Sol 时改为 `REPORT_MODEL_PROVIDER=openai`，在本机 `.env` 配置 `OPENAI_API_KEY` 和 `OPENAI_MODEL=gpt-6.1-sol`。适配器使用 Responses API、`reasoning.effort=low`、8192 tokens及 `store=false`；路由和具体问题每次请求30秒超时，整份报告的模块与整体总结每次90秒，不代表整轮问答总时限。每次重新提供已校验的问题和工具执行摘要，不续接供应商响应、不回传明文或加密推理内容。此方式不保留供应商推理状态，真实分类与分析质量仍需实连评估，`store=false` 也不等于零留存承诺。

使用用户指定的兼容网关时，额外设置基础地址（以下为虚构示例）：

```dotenv
REPORT_EXTERNAL_MODEL=on
REPORT_MODEL_PROVIDER=openai
OPENAI_MODEL=gpt-6.1-sol
OPENAI_BASE_URL=https://gateway.example.invalid/v1
```

基础地址不要包含 `/responses`、内嵌用户名密码、查询串或片段；客户端会追加 `/responses`。地址在业务登录前检查，仍只使用 `OPENAI_API_KEY`，不会自动使用DeepSeek密钥、业务token或Codex凭据。网关须兼容Responses的JSON与函数工具协议，失败回退本地，不自动转官方地址。选择自定义地址后启动提示显示“OpenAI兼容网关”。HTTP地址可按指定配置使用，但传输不加密；HTTPS可保护传输。

Codex是开发工具；其登录状态不是本项目的API凭据。2026-10-31按用户要求，本机已选择 `openai/gpt-6.1-sol` 并配置用户指定网关。此前官方直连超时；本轮通过网关鉴权、型号检查、语义客服路由及虚构报告模块总结实测，最终客服与模块总结共3次请求成功，194项离线回归通过。未读取真实报告。退出旧终端后重启读取新配置；密钥只填写本机 `.env`。

`glm-5.3-flash`、`glm-5.3-flashx` 和 `glm-5.3-flashx-legal` 使用开启思考的请求参数，单次输出预算为 8192 tokens、响应超时为 90 秒，兼顾思考与最终正文；思维链不进入后续请求或本地历史。其他模型沿用关闭思考、1800 tokens 和 30 秒超时的参数。最多5轮工具请求，第6轮只根据已读取事实生成结论；工具调用数或事实数达到预算时也提前结束查询并生成结论，不扩大总请求预算。模型兼容性及实际验证范围见 [AI 分析开发记录](../docs/development/agent-learning/2026-10-30-ai-analysis-strategy.md)。

开启后可直接问“分析我的报告”“分析下我的报告”“整体分析这份报告，说明哪些模块值得关注”“比较银行和非银行近7天申请情况”“那近一个月呢”，也可以问候、咨询申诉或人工客服。无关的普通知识仍返回服务范围说明。AI 分析不限于下述本地匹配语句；未开放的记录明细仍需本地查询。若失败，会使用固定提示区分模型超时、连接失败、服务拒绝请求、回答不完整、工具预算耗尽、请求敏感值冲突、路由格式、工具参数或调用顺序、统计事实出站及回答校验，再回到本地查询；不显示服务异常正文。

报告明细中的业务编号及普通文字不再登记为私有值，不因与问题、提示词或统计值重合而拦截。四类个人信息仍检查字段别名、登记标签、已知原值及常见格式；固定协议按完整字符串授权，分析正文的数字须来自实际引用的事实。

固定提示词、协议键名、模型名称、状态和程序生成的引用按完整字符串登记，避免报告明细中的 `type`、`null` 等文本与协议重合时误报“请求内容与本地敏感值冲突”。该处理不豁免用户问题、动态目录文字或分析正文；模型调用标识使用程序生成的引用重建。每轮查询会提供剩余预算；已有事实时，超出总调用数或字段数的追加查询整批跳过，再依据已读取事实生成结论，仍须通过引用和数值检查。更新后退出旧进程，重新运行 `main.py` 生效。

## 小贝客服与解读风格

助手采用“小贝🐚”的身份。整份报告按“第一个模块的小结 → 后续模块的小结 → 整体总结”回答，每个模块默认一句，关键记录或缺失需要说明时再补第二句，必要时自然提及少量关键数字；不列出每个字段、引用编号和重复规则。具体指标先直接给结果，只补与当前问题有关的必要解释；已确认的次数、学历、状态等简单短答不追加信用评价或服务介绍。不会复制其他对话中的分数、个人资料、排名或信用评价。零值不直接概括为无风险；只使用已核实的当前版本评分规则。实现和验证见 [模块总结记录](../docs/development/agent-learning/2026-10-31-module-overview.md)、[客服表达记录](../docs/development/agent-learning/2026-10-30-xiaobei-service-conversation.md) 和 [持续评测记录](../docs/development/agent-learning/2026-10-31-customer-evaluation.md)。

例如默认分档下的虚构31分，回复为：“您的报告分数是31分，属于‘待提高’。”这不是用户真实分数；取整和等级区间在本地核对，不作为客服正文展开。

评分展示覆盖普通仪表盘版本1、2、3、4、6、50、52的主分析指数，及版本40的指数评分；不把社交扫描分数当作报告总分。普通版按取整前数值判断默认区间，模板配置1至5档时使用当前自定义区间，6档及以上仍按页面实际默认三档，重叠区间最后匹配生效；版本40先取整再分级。缺失、空值或非法值不当成0；模板规则无法确认时只说明已有分数，不猜等级。本地自然分数查询及模型失败时也使用同一展示说明，显式 `/find`、`/pick` 仍保留本地资料查询用途。该功能只解释报告已有分数的展示和分档，不重算底层评分模型或推断审批结果。

2026-10-31此次客服表达调整后207项离线回归通过。另用虚构69.5分报告实连Sol兼容网关，5次请求完成工具查询和答复，正确显示70分、等级一般，不含字段清单或读取范围；真实用户报告未参与验证。

常见短句在本地即可答复，其余说法在开启AI后由语义路由选择主题：

| 场景 | 示例与行为 |
|---|---|
| 问候 | “你好”：介绍小贝及可提供的服务 |
| 感谢 | “谢谢”“谢谢，这次明白了”：本地简短回应；感谢后还有报告问题时继续回答该问题 |
| 人工、申诉、退款 | “人工”“我要申诉”“我能退款吗”：提供联系渠道及说明，不提交工单、申诉或退款 |
| 数据来源 | “你们数据哪里来的”：引导核实具体模块来源，不虚构国资背景、合规授权或提供方 |
| 贷款、申请频率 | “我能贷款么”“分数高为什么贷不下来”“多久申请一次正常”：说明判断边界和可继续核对的报告指标，不保证获批或编造正常间隔 |
| 个人字段 | “我的名字 身份证”：仅本地说明查询途径，不断言报告缺少这些字段，也不外发身份信息 |
| 报告列表与关注内容 | “我有哪些报告”“我的关注内容是什么”：说明当前报告范围、业务模式下的 `/orders` 或本地检索方法，不猜名下总数或栏目不存在 |

客服热线、邮箱和时段采用用户2026-10-30提供的Dify话术，未独立核验；退款条件、处理时效与数据来源背书未提供，因此不扩写为既定政策。客服回复成功保存后清空旧报告指代，不向模型发送完整客服历史。具体实现和验证见[开发记录](../docs/development/agent-learning/2026-10-30-xiaobei-service-conversation.md)。

以下本地模式也支持“我有没有逾期记录”“最近一周非银申请了几次”“近7天贷款机构数帮我看一下”。本地匹配支持近7天、近15天、近一个月、近半年等周期表达，其他周期须有本报告的登记字段；上个月、今年等自然月或日期范围不会替换成滚动周期。本地匹配一次指定多个不同周期会提示分别查询；AI 模式可选择多个已登记周期，但不能把重叠窗口相加。

`/find 关键词` 在本地字段资料中搜索，最多列出 6 项；用 `/pick 序号` 或“选择第1项”选定字段后读取。选定后可以追问“这个是什么意思”“它的值是多少”“那近1个月呢”；切换周期限定在同模块、同指标，不能找到时明确提示。多字段匹配时先让用户选择，不混用字段口径；自然问法匹配超过6项会提示补充模块、字段名或周期。申请总次数不会以机构数、夜间申请等分项代替；档位仍按档位显示，不换算成精确次数。

未提供、`null`、空字符串与 `0` 分别显示；不会把缺失值改成 0，也不会根据 0 断言从未申请。本地模式和 AI 失败回退中，“分析下我的报告”“帮我分析这份报告”等整体问法列出可查模块和下一步示例，不再提示未找到某个指标；AI 模式会自主选取统计项分析并显示本轮依据。无法识别的本地问题显示当前版本可查模块和检索示例；未知新问题和切换报告会清空旧字段指代。

## 历史与日志

完整问题、答案和报告绑定信息在写入 SQLite 前由当前 Windows 用户的 DPAPI 加密，数据库位置为 `%LOCALAPPDATA%\ReportAssistant\history.sqlite3`。`/history` 回看当前报告最近 50 条记录；恢复的完整历史不进入模型请求。加密失败时停止保存，不生成明文备用文件。当前实现仅支持 Windows；DPAPI 绑定当前操作系统用户，不提供业务多账号或 Web 会话的访问控制。

SDK、HTTP 客户端及已有子日志输出器被关闭；终端错误采用固定提示，不输出请求头、业务响应、SDK 异常正文或 traceback。用户主动查询的答案和 `/history` 会在本地终端显示完整内容。

```powershell

.\.venv\Scripts\python.exe -X utf8 scripts\evaluate_bulk.py --plan
# 使用本机.env的模型执行真实问答，每轮可能发起多次模型请求。

```

`--limit 32`可先执行32个会话，`--workers`支持1至64，需按模型服务承载选择；高并发结果不能代表单用户延迟。输出默认位于被Git忽略的`.eval/bulk-10000/`：`manifest.json`是题库和独立预期，`answers.jsonl`逐会话追加问题、回答、来源及失败，`progress.json`是最新完整会话统计。恢复按题目摘要匹配，半截尾行先备份；只计每题最新完整结果，旧失败仍保留在原记录中，跨源码版本分别记账。自动通过仍需语义复核，服务超时和本地回退不计为模型成功。实际执行情况与修复见[万次模拟记录](../docs/development/agent-learning/2026-11-02-ten-thousand-evaluation.md)。

默认并发改为2：本机网关16并发试跑出现集中超时。单次运行可加`--retry-stale`重新验证旧源码/模型配置版本的题目；进度中的`current_version_cases`与`current_version_passed_cases`分别表示本版本执行数和自动通过会话数，不能把跨版本累计完成数当成同版本通过。

`--continuous`每批启动新进程加载代码，默认32个会话；持续模式主动补跑旧版本结果，网络失败在同版本下最多累计3次完整尝试（`--max-network-attempts`可调），业务断言失败保留待修复。某批至少一半会话出现超时、连接或服务错误时减半并发，退避60秒起、最多300秒；连续三批达到该条件时停止并标明`service_unavailable`。`runner.json`每10秒记录监督进程、子进程和运行状态；批间更新完成数，逐题统计以`progress.json`为准。`awaiting_semantic_review`仅表示本版本全量自动通过，`completed_with_failures`表示执行完成仍有失败。创建输出目录下的`stop.request`可在当前批结束或退避期间停止；再次续跑前移除该标记。文件锁防止两个进程同时追加同一目录，异常退出会自动释放锁。
